# Мобильное приложение Социальной Сети (Android)

🛠 Технический стек и архитектура проекта Язык разработки:** Kotlin
* **Архитектурный паттерн:** MVVM, Clean Architecture, паттерн Repository, Unidirectional Data Flow (UDF)
* **Асинхронность и реактивные потоки:** Kotlin Coroutines, StateFlow, SharedFlow
* **Пагинация и работа со списками:** Jetpack Paging 3 (PagingData), RecyclerView, DiffUtil
* **Внедрение зависимостей (DI):** Hilt (Dagger)
* **Сетевой слой:** Retrofit 2, OkHttp 3, REST API
* **Локальное кэширование (СУБД):** Room Database, SQL
* **Интерфейс (UI):** XML Layouts, Material Design Components, Custom Views, Рендеринг изображений (Glide)
* **Push-уведомления:** Firebase Cloud Messaging (FCM), Huawei Mobile Services (HMS)

## 📱 Функциональные возможности и экраны

### 1. Гостевой режим (Неавторизованная зона)
* Приложение предоставляет возможность безопасного просмотра основной ленты постов без авторизации.
* Реализована логика ограничения доступа (Guard-интерфейсы): при попытке перехода на вкладки «События», «Пользователи» или при интерактивном взаимодействии с контентом (лайк, репост) приложение запускает сценарий авторизации/регистрации.

### 6. Глобальная лента публикаций и пагинация данных
* Нижняя панель навигации (Bottom Navigation Bar) обеспечивает бесшовный переход между ключевыми хабами: Посты, События, Пользователи.
* **Оптимизация трафика и памяти:** Загрузка ленты публикаций реализована с помощью библиотеки **Jetpack Paging 3**. Данные стримятся в UI в виде потока `PagingData`, что обеспечивает плавную бесконечную прокрутку, автоматическое кэширование и предотвращает утечки памяти при работе с большими массивами данных.
* **Создание и редактирование контента:** Реализован многофункциональный редактор. Поддерживается ввод текста, прикрепление внешних ссылок, динамическая загрузка изображений/медиафайлов, а также механизм упоминания других пользователей системы (Mentions). Все CRUD-операции мгновенно синхронизируются с сервером через REST API и обновляют локальный кэш Room.

### 7. Создание постов и CRUD-модуль постов

### 8. Модуль динамического редактирования публикаций
* При выборе действия «Изменить» в контекстном меню публикации, приложение инициализирует навигационный переход на фрагмент редактирования контента с передачей текущих метаданных поста.
* **Синхронизация состояний:** Внутри фрагмента разворачивается предсказуемый сценарий обновления данных, где пользователю доступно:
    * Корректировка текстового тела публикации и актуализация внешних ссылок.
    * Модификация медиа-вложений (удаление старых ассетов и загрузка новых файлов из локального хранилища).
    * Динамическое изменение списков упомянутых пользователей (Mentions) с мгновенным обновлением связей на UI и валидацией изменений перед отправкой.
* После подтверждения операции измененный стейт отправляется на бэкенд через PATCH/PUT-запрос REST API, после чего библиотека Room автоматически инвалидирует локальный кэш, и обновленный пост реактивно перерисовывается в общей ленте без необходимости перезагрузки всего списка.

### 8. Экран детального просмотра (Detail Fragment) и оптимизация вложенных списков
* Реализован фрагмент детального просмотра публикации, который агрегирует и отрисовывает полные метаданные объекта: расширенное текстовое описание, медиа-вложения высокого разрешения, точные таймштампы и списки интерактивного взаимодействия (Likes & Mentions).
* **Кастомная UI-логика списков:** Для отображения участников, оценивших публикацию или упомянутых в ней, разработан кастомный горизонтальный UI-компонент на базе `RecyclerView`.
* **Оптимизация производительности интерфейса:** Чтобы предотвратить избыточное выделение памяти и перегрузку UI-потока (Main Thread) при отрисовке сотен аватаров, имплементирована логика условного сворачивания (Collapse/Expand):
    * При количестве вовлеченных пользователей до 5 человек списки отрисовываются на основном экране в реальном времени.
    * Если количество превышает лимит ( > 5 ), компонент автоматически инкапсулирует хвост списка и генерирует интерактивный элемент `+N`.
    * По нажатию на элемент `+N` приложение инициализирует навигационный переход или открывает кастомный диалоговый компонент со встроенным вертикальным `RecyclerView` и оптимизацией через `DiffUtil` для просмотра полного списка пользователей.

### 9. Архитектура модуля мероприятий (Event Management)
* Разработана полноценная подсистема для организации и мониторинга внутренних мероприятий платформы, доступная через выделенный хаб в панели нижней навигации.
* **Реактивная архитектура на StateFlow:** Логика отображения ленты событий полностью построена на принципах Unidirectional Data Flow (UDF). Состояние экрана (загрузка, кэшированный контент, ошибки сети и динамические изменения подписок) инкапсулировано во ViewModel и транслируется в интерфейс через **StateFlow**. Это обеспечивает мгновенную реактивную перерисовку UI при получении новых данных и полную сохранность стейта при повороте экрана устройства.
* **Агрегация метаданных:** Каждая карточка события в `RecyclerView` представляет собой сложный компонент, объединяющий обширный массив данных:
    * Тематическое описание мероприятия и прикрепленные медиа-вложения.
    * Формат проведения (дифференциация на Online / Offline сессии).
    * Временные метки: точная дата создания карточки и дата непосредственного проведения ивента.
    * Счетчик вовлеченности: динамическое отображение текущего количества участников.
* **Навигация:** На экране интегрирована кнопка Floating Action Button (`+`), инициализирующая безопасный навигационный переход на фрагмент конфигурации и создания нового мероприятия.

### 10. Модуль конфигурации и публикации мероприятий
* Разработан многофункциональный экран создания новых ивентов, предоставляющий пользователю гибкий инструментарий для наполнения и валидации метаданных будущего события перед отправкой на бэкенд.
* **Инструменты ввода и кастомизации:**
    * **Контентный слой:** Текстовое описание сути мероприятия и модуль прикрепления бинарных файлов через интеграцию со встроенным Storage Access Framework (SAF) Android.
    * **Тайм-менеджмент:** Реализован интуитивный выбор временных рамок с использованием нативных диалоговых компонентов `DatePicker` и `TimePicker` для точной фиксации даты и времени проведения.
    * **Управление спикерами:** Интегрирован механизм назначения ведущих (Speakers) с возможностью интерактивного поиска и отметки зарегистрированных пользователей платформы по их уникальным ID.
    * **Конфигурация формата:** Добавлен UI-переключатель для определения типа сессии (дифференциация логики на Online-трансляции и Offline-встречи) с последующим динамическим изменением структуры отображения карточки в общей ленте.

### 11. Интерактивный экран детального просмотра мероприятия (Event Detail Fragment)
* Разработан специализированный фрагмент для детального отображения информации о мероприятии, который консолидирует полные метаданные объекта на едином экране.
* **Консолидация данных:** UI-компоненты динамически визуализируют расширенное текстовое описание, медиа-вложения, списки организаторов, назначенных спикеров (ведущих), а также полный перечень зарегистрированных участников.
* **Реактивная механика подписок (State Management):** Реализован интерактивный механизм вовлечения пользователей через кнопки действия «Принять участие» и «Покинуть событие».
* **Асинхронная синхронизация:** При инициации действия приложение отправляет асинхронный POST/DELETE запрос к REST API бэкенда. Счетчик участников и стейт активности кнопок реактивно пересчитываются и обновляются через StateFlow в реальном времени, обеспечивая консистентность данных между сервером и UI-слоем.

### 12. Модерация контента и управление жизненным циклом событий владельцем
* Реализована ролевая модель доступа к управлению контентом: для карточек мероприятий, где текущий авторизованный пользователь является создателем (автором), динамически отрисовываются элементы управления в ленте.
* **Инструменты модерации (CRUD-логика):**
    * **Удаление контента:** Инициализирует асинхронный DELETE-запрос к REST API. При успешном ответе сервера запись мгновенно удаляется из локальной базы данных Room, а библиотека Paging 3 / RecyclerView реактивно обновляет UI без полной перезагрузки ленты.
    * **Редактирование данных:** Осуществляет навигационный переход на фрагмент редактирования события с передачей текущего стейта объекта, предоставляя автору возможность актуализировать текстовое описание, изменять временные рамки (через Date/TimePicker) или переназначать состав ведущих (Speakers).

### 13. Модуль динамической модификации метаданных мероприятий
* Разработан фрагмент редактирования существующих событий, архитектурно унифицированный с модулем редактирования публикаций (постов).
* **Компонентный перенос данных:** При инициации режима редактирования фрагмент принимает текущий стейт события, автоматически заполняя поля ввода актуальными данными (текст, установленный формат, выбранные спикеры и временные метки).
* **Валидация и синхронизация изменений:**
    * Инкапсулирована логика перезаписи контентного слоя (текст, медиа-вложения через SAF).
    * Обеспечена возможность динамической корректировки даты и времени проведения через повторный вызов диалоговых компонентов `DatePicker` и `TimePicker`.
    * Реализована функция переназначения списка ведущих (Speakers) с валидацией изменений на клиенте.
* После отправки измененных данных на бэкенд через PATCH/PUT-запрос REST API, реактивные потоки данных обновляют локальный кэш Room, обеспечивая мгновенную консистентность интерфейса во всех связанных вкладках приложения.

### 14. Директория пользователей платформы и масштабируемость профилей
* Разработан глобальный экран просмотра списка всех зарегистрированных участников социальной сети, доступный через выделенную вкладку нижней панели навигации (Bottom Navigation Bar).
* **Оптимизация производительности списков:** Отрисовка карточек пользователей реализована на базе `RecyclerView` с использованием механизма `DiffUtil` для вычисления разницы между списками в фоновом потоке, что обеспечивает плавный скроллинг и минимальные затраты на перерисовку интерфейса.
* **Архитектурный задел под масштабирование:** Бизнес-логика и навигационный граф приложения спроектированы с учетом переиспользования компонентов (DRY). Архитектура подготовлена под бесшовную интеграцию экранов публичных профилей других пользователей: при клике на карточку участника запускается сценарий перехода на унифицированный фрагмент профиля с динамической подгрузкой персональной ленты постов и мест работы выбранного пользователя по его уникальному ID.
